# 本輪修正與驗收紀錄

日期：2026-09-14；App 版本：`2026.09.14.1`。依使用者「把 repo 完善」的要求，處理上一輪審查列出的 17 項問題，保留原有未提交修改、PDF、個案資料及 `.env.local`。未提交 Git、未部署、未呼叫真實 Gemini。

這是一輪工程修正與來源定位驗收，不是所有癌別、病程與處方的完整臨床認證。

## 使用者需求如何落地

- 不必先找 PDF：首頁可直接開始；先問目前病程、治療階段、ECOG，其他欄位按情境展開。沒有來源時保留資料整理，不捏造來源頁或療程。
- 搜尋立即有回應：結果放在搜尋框正下方，搜尋時收起品質總覽；結腸／直腸分開進入專屬表單，舊 umbrella 快速參考連結也會先要求選部位。
- 結果先看重點：一張主卡呈現方向、下一步、必要原頁。Gemini 整合在同一張卡；無有效來源的 AI 回答不取代原本整理。完整來源、規則、原始候選及健保限制按需展開。
- 原乳癌案例：程式輸出「高風險 ER-low：優先討論輔助性化療」，不再強制等待未取得的 RS；真實來源測試限定 BINV-6 PDF p.19 與 BINV-M PDF p.72。這是個別化風險討論提示，不是宣稱 ER-low 本身構成 NCCN 新的化療門檻或化療效益必然確定。
- 多癌別共通處理：同一套目前病程、衝突、來源版本與空候選防護供頁面、療程、AI 及健保候選使用。專屬術後評估仍限乳癌、NSCLC、結腸癌、直腸癌；其他癌別與未覆蓋病程明示僅來源候選整理。

## 更新與後續使用

1. 重新啟動本機 `npm start`，再重新整理原分頁；設定頁版本應為 `2026.09.14.1`。
2. 文件庫按「一鍵升級」，在本機補齊舊索引的來源文字／腳註。不需重新匯入 PDF；舊索引仍可閱讀。只有使用者啟動解析後才更新自己的 IndexedDB。
3. Gemini 前先檢查實際傳送內容、去識別與來源使用權。未勾選／未按整理就不傳送；沒有有效證據的 AI 摘要保留規則初步整理。

本輪沒有修改或顯示 key，沒有消耗 Gemini 額度、擅自部署或修改使用者的本機 PDF。測試伺服器是 API 關閉的隔離 origin；驗收完成後已停止伺服器並關閉測試分頁，原本的 4173 預覽未關閉。
