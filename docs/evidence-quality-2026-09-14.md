# 選頁與 Gemini 來源包改善

版本：2026.09.14.2。範圍是檢索品質、安全傳送與可追溯性，不重訂臨床治療規則，也不代表全癌別醫療審核完成。

## 對應使用者需求

- 仍由病人情境開始，沒有 PDF 也可填條件、查看缺漏；缺少來源時不請 AI 補出治療結論。
- 原 ER-low／停經後／pT2N1 個案保持 BINV-6 PDF p.19 與 BINV-M PDF p.72；不擴張成全部 BINV-M 或其他受體分支。
- 共用機制改善其他情境：明確病程標題排除、既有標記極性規則、同文件連結追溯、數量與文字上限，以及模型逐頁適用性自查。
- 主畫面維持精簡；新增可展開的選頁與排除理由。NCCN、TFDA、健保仍分開；腳註不會自動加入療程按鈕。

## 工程變更

1. quickref 不再在上游偷偷截取 12 頁；保留全部候選後才建立來源包。沒有任意以分數前 N 頁冒充完整證據。
2. 來源包記錄逐頁用途、理由、必要來源識別及清單。必要引用限定同文件；多部分章節需明確定位，不選第一個章節名稱出現處。循環連結只保留一份。
3. PDF 新增 source context v2：保留有效章節文字、明確 FOOTNOTES FOR／footnotes on／Footnotes (...) 關係及部分號碼。更新摘要、索引和一般文獻頁不當成來源目標。一般延伸連結與可選療法 eligibility 提示不盲目遞迴。
4. 超量時來源 evidence 整包為空且 blocked，不默默切頁、切文字或切掉第 25 個療程後還說完整。上限：12 頁、16,000 字元／頁、60,000 字元總文、480,000 UTF-8 bytes 封包。
5. 後端在讀取 key／呼叫 provider 前重新檢查來源包及個案阻擋狀態。Gemini 回覆須逐頁自查、主結論附主決策／療程／候選頁引文；不能只引用腳註作主結論。
6. 前端要求來源檢查版本標記；若後端尚未重啟、仍回傳舊版摘要，保留本機初步整理並提示重啟，不把舊摘要當成通過新檢查。

## 仍需明確保留的限制

- 這是文字與已辨識引用關係，不是完整 PDF 流程圖理解；未辨識的箭頭、跨欄條件、別種腳註寫法仍可能漏掉。
- conditionalReferences 只是可選療法的適用條件提醒；未提供那些原頁時，模型必須列為待核對，不能確認療法適用。不是所有引用都已自動補全。
- 頁數少不等於一定正確。單頁內仍可能有互斥分支；模型逐頁自查與引文存在檢查都不能保證推論／適用性正確。
- 其餘癌別仍主要是規則與候選檢索，未建立全癌別逐病例、逐來源的獨立臨床 golden set；不報虛構準確率。
- 本輪沒有執行 `audit:nccn-all`，不宣稱 69 系列全數通過。也未測試真實 Gemini 的摘要品質或耗用額度。
- 沒有啟用網路搜尋，沒有修改／讀出 API key，沒有上傳 PDF、修改原始文件或部署。來源文件授權與去識別傳送同意仍需使用者確認。

## 使用更新

重新啟動原本本機伺服器（`npm start`）並重新整理原網址。文件庫會對需要升級的索引提供重新解析；此步驟在本機處理，勿清除瀏覽器資料。使用 Gemini 前，查看「選頁理由與完整性」並處理缺漏；通過只是可供 AI 整理，不等於醫療審核通過。
