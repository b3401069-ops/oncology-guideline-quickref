## 健保 PDF 自動解析

- 匯入健保第 9 節或抗癌瘤藥物給付規定後，可在 PDF 文件庫點「解析健保規定」。
- App 使用本機 PDF.js 擷取文字，不會把 PDF 上傳；解析時會顯示頁面進度。
- 系統依 9.x 藥物條目與癌別名稱建立「PDF 自動擷取」健保資料，保留來源文件、條號及頁碼。
- 解析時會記錄公告／生效日期、來源文件、版本、條號與頁碼；新版同藥物規定會成為目前版本，舊的自動擷取資料改為封存而不刪除，手動資料不受影響。
- 表格、掃描頁、跨頁或無法對應癌別的條目會列入解析摘要，必要時仍需人工核對。自動擷取不等於個案已通過給付資格審查。

## 功能特色

- 🩺 **個案先行工作台**：不必先準備 NCCN PDF；先選癌別、填入病程與生物標記，再查看缺漏及可核對的指引候選。沒有原始來源時只標示待核對，不產生 NCCN 療程或頁碼
- 🔍 **全癌別搜尋**：支援中文、英文、同義詞模糊搜尋
- 📄 **本機 PDF 文件庫**：匯入、管理、版本控制指引 PDF
- 🌐 **來源中心**：集中健保第 9 節抗癌瘤藥物、整份給付規定與 NCCN 官方入口
- ✅ **防漏 Checklist**：自動預載共同與癌別專屬必查項目，可編輯、可分類
- 🎯 **精準化欄位**：依癌別預載分期、病理、PD-L1 與相關基因欄位，留白不阻擋輸出
- 🏥 **選藥後查健保**：快速參考先選藥物／療程，再展開限制；缺少必要條件時可就地補填並重新比對
- 📋 **快速參考**：一鍵產生參考方向；可選擇按下 Gemini 按鈕，把去識別化的結構化欄位與候選段落濃縮成更短的臨床重點
- 💾 **本機儲存**：PDF 與 App 資料儲存於 IndexedDB；只有使用者主動按下 Gemini 按鈕時，才送出畫面已列明的去識別化摘要資料
- 📱 **PWA 支援**：可加入 iOS / Android 主畫面，支援離線使用

## 使用方式

### 本機啟動（含 Gemini）

1. 複製 `.env.example` 為 `.env.local`。
2. 只在 `.env.local` 填入 `GEMINI_API_KEY`；此檔已被 Git 忽略，不要把 key 放進 `index.html`、localStorage 或提交紀錄。
3. 啟動 App：

```powershell
npm start
```

然後開啟 `http://127.0.0.1:4173`。若未設定 key，原本規則式快速參考仍可使用，但 Gemini 按鈕會顯示設定提醒。

建議一律使用 `npm start`，不設定 key 就不啟用 AI。請勿對含 `.env.local` 的原始碼目錄直接啟動一般靜態伺服器，以免其暴露設定或測試檔案。

### 部署

目前 `server.cjs` 僅支援個人本機使用，綁定 `127.0.0.1`，驗證 Host／Origin、JSON 與同源自訂標頭，並限制請求大小、頻率、同時處理數及逾時。這不是多人／公開部署的身分驗證機制，不可直接改綁公開介面後上線。

靜態託管只能提供不含 AI 的前端，而且必須使用明確的公開檔案清單，排除 `.env*`、後端、測試與私人文件。若要 Cloud Run／多人使用，需要另行設計登入授權、每使用者配額、秘密管理、資料治理與 HTTPS；本輪未部署也未驗收上述能力。API key 不可編入前端。

正式手機安裝需使用 HTTPS 網址。

## 指引與健保文件下載

### 健保給付規定下載在哪裡

App 內新增「來源中心」，可從首頁或底部導航進入：

- **健保第 9 節：抗癌瘤藥物**：腫瘤用藥給付最常用 PDF。
- **健保藥品給付規定：整份帶走**：需要完整章節時使用。
- **最新版藥品給付規定內容（分章節）**：官方更新後用來確認第 9 節最新版。

下載 PDF 後，回到「PDF 文件庫」→「+ 單筆」或「批次匯入」，來源填「健保給付規定」。

健保結果採保守呈現：有明確資料時顯示「健保有相關給付，但有限制條件」並逐項列出；條件欄位未填或規定尚未核對時顯示「資料不足／尚待核對」，不會直接判定為沒有給付。快速參考會合併手動資料、健保 PDF 自動擷取條目與 NCCN 療程成分，點選後只展開該項限制。

### NCCN 指引

NCCN 指引通常需要在 NCCN 官方網站登入後逐份下載。這個 app 目前不保存 NCCN 帳密、不自動登入、不批量抓取 NCCN PDF，避免違反登入與授權邊界。

可以自動化的部分是：

- 集中開啟 NCCN 官方 guideline 入口
- 提醒本機 NCCN PDF 超過 6 個月未確認版本
- 協助匯入、設為目前版本、封存舊版
- 在本機逐頁建立版本、章節代碼、治療相關頁及原始 PDF 頁碼索引
- 依目前輸入的病程、線別、病理與生物標記，排序優先查閱頁面並列出 PDF 擷取候選選項
- 發現互相矛盾的條件時先警示，不把候選選項顯示成最終治療決策

既有 PDF 不必重新匯入：到「PDF 文件庫」按「一鍵升級」即可逐份補建索引與來源文字。之後匯入新版時，照常設為目前版本；App 會把該份列為待解析。索引能自動重建，不代表既有臨床規則可自動沿用新版本；專屬分支遇到尚未核對的版本會降為待核對，需經原頁與案例驗收後才能更新版本範圍。

## 操作說明

### 1. 初次使用

1. 開啟 App，會看到全癌別分類列表
2. 可由「直接開始個案」搜尋癌別，先填目前掌握的條件；此步驟不要求先匯入 PDF
3. 快速參考頂端會區分個案資料整理、本機 NCCN 文件，以及已連結的個案分支與頁碼
4. 所有癌別預設為「待維護」狀態；也可開啟來源中心或開始匯入指引 PDF

### 2. 匯入 PDF

1. 點擊「PDF 文件庫」→「+ 單筆」或「批次匯入」
2. 如不知道文件來源，先進「來源中心」開官方下載入口
3. 選擇已下載的指引 PDF
4. 填寫指引名稱、來源、版本
5. 選擇對應癌別（可多選）
6. 設為目前版本或歸檔

批次匯入在手機上每頁只顯示 10 份，並逐檔寫入。畫面會顯示實際收到的檔案數、總容量與瀏覽器估計可用空間；單一檔案失敗不會中止整批，重試時會略過已成功項目。若 OneDrive 回傳 0 位元或無法讀取的雲端檔案，請先下載到裝置後再重試失敗項目。

NCCN 批次匯入完成後，到文件庫按「解析全部 NCCN」。解析會逐份、逐頁在本機進行，單一文件失敗不會中止其餘文件；請保持 App 開啟。完成後每份文件卡會顯示版本、章節頁數與治療相關頁數。

解析器會把候選頁分為「具體建議、治療路徑、治療原則、檢查評估、補充資料」，快速參考優先顯示具體建議與治療路徑。拆出的選項同時標示手術、放射治療、藥物／全身治療或追蹤，並保留 NCCN 章節碼、PDF 頁碼及可解析的後續步驟連結。

「我要更精準」欄位有值時，App 會使用病程、治療線別、病理分類與分子標記比對候選；陰性標記會阻擋明顯衝突的療程。這仍是本機自動擷取的快速參考，需以原始 NCCN 流程圖、腳註及完整病況做最後核對。

真實 PDF 回歸檢查分成兩層：`audit:nccn` 精準驗證 HCC、NSCLC、SCLC、乳癌、直腸癌、前列腺癌及神經內分泌／腎上腺腫瘤；`audit:nccn-all` 會先比對 69 套預期 NCCN 指引並直接列出缺少名稱，清單齊全後才逐份檢查章節、治療頁、療程選項，以及常見或疾病專屬條件能否帶出全身治療。

整批 PDF 更新後可執行：

```powershell
$env:NCCN_PDF_DIR='C:\path\to\NCCN App PDFs'
npm run audit:nccn-all
```

### 3. 編輯癌別

1. 進入癌別詳情頁
2. 點擊「編輯此癌別」
3. 可編輯：
   - 基本資料（中英文名稱、同義詞）
   - 指引路由（主要/次要指引）
   - 必查章節（每行一筆）
   - 外部連結

### 4. 使用「不要漏」Checklist

1. 第一次開啟新版時，App 會保留既有內容並補入共同與本癌別專屬項目
2. 可自行勾選、編輯或刪除；刪除後不會在每次啟動時自動加回
3. 需要還原時，點「加入本癌別範本」只補回缺少的同名項目

### 5. 使用「我要更精準」欄位

1. 每癌別會預載共同欄位，以及適用的病理、分期、PD-L1、基因或風險欄位
2. 可新增、修改或刪除單選、多選、文字與數字欄位
3. 所有欄位可留白，不阻擋快速參考；範本只用來整理資料，不直接產生治療結論

### 6. 快速參考

1. 進入癌別 → 點擊「📋 快速參考」
2. 先看「本次個案重點」：主要方向、當下行動、必要原頁。
3. 需要時展開來源與輸入、規則判讀、防漏清單；選定療程才核對健保／TFDA。
4. 「複製本次重點」只複製目前顯示的短摘要；「複製完整核對紀錄」保留詳細資料。

快速參考中的補填值只保留在目前分頁，不會寫回癌別固定欄位；按「新個案／清除條件」會清除本次條件與選藥。

#### Gemini 資料與證據邊界

- 預設不傳送。展開 Gemini、檢查「本次實際傳送內容」、確認去識別與有權傳送後，才勾選同意並按整理。
- 傳送至 Google 的是已填欄位、允許的治療歷程欄位、規則摘要、已定位來源頁文字與候選條件；不送完整 PDF 檔案，也不送 PDF 儲存識別碼。自由文字仍須由使用者去識別，App 不保證自動移除個資。
- 本實作沒有啟用搜尋工具；答案基於送入資料與模型既有知識，不是即時上網查證。
- 主要結論、理由與行動需附來源識別及可在送入文字中找到的引文。無有效引用、來源截斷／缺完整脈絡、病程不明或資料衝突時，不能保留確定性治療結論。
- 引文存在只證明文字可追溯，不等於推論正確或適用這位病人。PDF 流程箭頭、腳註、例外、藥品核准、健保條件及醫療判斷仍需人工確認。
- 去識別化不等於取得指引的 AI 使用授權。使用者須另外確認來源文件權利與機構規範；程式不代為授權。
- API 使用 `store: false`，僅表示不要求保存可供後續取得的 interaction，不能據此宣稱 Google 完全不保留資料；請另依適用的供應商條款評估。請求格式依 [Google Interactions API 文件](https://ai.google.dev/api/interactions-api)。

若不使用 Gemini，保持未勾選／不按整理即可；也可由使用者移除本機 key 後重啟伺服器。已傳送內容不會因取消勾選而自動撤回。

### 開發驗證

#### 病況聚焦、頁內定位與人工覆核（2026.09.14.5）

1. **最多兩個關鍵追問**：快速參考上方選擇本次問題；先補畫面提示的兩項，再按「套用並重新定位」。未知值不當成陰性或 RS 0。這是下一步追問，不是完整醫療資料清單。
2. **依問題聚焦**：「是否需要本次治療」先收斂主決策頁；必要腳註仍會補回。「選擇療程」保留主頁及療程脈絡、改變 AI 整理重點。乳癌停經後的「標靶／免疫適用條件」另補同版 BINV-K p.68；原案例的整體方向仍維持 BINV-6 p.19 與 BINV-M p.72。
3. **頁內定位**：目前支援 Breast v5.2026 BINV-6 p.19 的部分停經後先手術分支，以及 Colon v2.2026 COL-4 p.13 的 pMMR/MSS 低／高風險 III 期列。展開「查看本次頁內分支」可開啟原頁標示位置。整頁與腳註保留，不只傳裁切段落；未完成檢測時保留仍可能適用的方向。其他版型、旋轉頁、座標或文字檢查失敗，回退整頁，**不是已完成全癌別箭頭辨識**。
4. **療法條件檢查**：目前為乳癌 CDK4/6 與 NSCLC 部分術後標靶／免疫的已編碼條件。區分已記錄條件符合、尚缺資料／來源、已知條件不符；未建立完整規則（如 olaparib）的療法維持待核對。缺頁或缺前置療程時，不讓受檢療法變成 AI 結論／行動或 NCCN 健保選藥候選。這不等於完整處方資格、TFDA 核准或健保給付。
5. **標準案例覆核**：首頁「品質稽核」提供 6 個固定案例，獨立列預期頁（含必要腳註）、禁用頁、停止條件與工程差異。初始全部待醫師覆核；須具名、寫註記並確認已核對原頁，才可儲存確認。紀錄綁定案例內容及 PDF SHA-256；改來源／案例會失效，但程式改壞仍會顯示已覆核案例的回歸失敗。無覆核樣本時不顯示臨床漏頁率數值。

覆核紀錄保存在目前網址的本機 localStorage，請用該區的「匯出案例與覆核紀錄」另外保存；目前不包含在既有資料備份／自動還原流程。匯出的是固定案例與來源指紋，不是正在輸入的病人資料或 PDF。

更新後重新啟動 `npm start`，在**原本網址**重新整理／按「更新」，再到文件庫重新解析需要使用的 PDF，建立 `branchContextVersion: 1` 的座標與來源指紋。不需要清除資料、重新匯入 PDF 或重填 key。詳細驗證與限制見 [第二輪改善紀錄](docs/workflow-round2-2026-09-14.md)。

#### 選頁與 Gemini 來源包（2026.09.14.2）

- 先按本次病程／專屬分支選頁，再補入同一 PDF 明確連結的腳註；不把所有「See」連結都當成必要治療證據。一般候選可排除明確不符的病程標題，以及全部選項均與已填標記衝突的療程建議頁；未知值不等於陰性。
- 「選頁理由與完整性」可展開查看主決策、療程／支持、必要腳註、入選理由及排除理由。主畫面仍只顯示重點來源；補入的腳註不會自動變成健保療程。
- 不再默默截取前 12 頁。來源超過 12 頁、單頁超過 16,000 字元、全文總量超過 60,000 字元或封包超過 480,000 UTF-8 bytes 時，停止 AI 傳送並提示縮小問題。這些是工程上限，不是醫療可信度分數。
- 只解析出文字不足以通過來源檢查。舊索引需在文件庫重新解析成 `evidenceContextVersion: 2`；已辨識的必要連結缺頁或章節有多個無法區分的部分時，也會停止 AI 傳送。
- 前、後端共用封包檢查，重新核對頁數、來源識別、文字限制及必要連結；這只能驗證收到的清單內部一致，不能證明解析器沒有漏辨識內容，也不是對惡意客戶端的來源真偽認證。
- Gemini 需對每頁提供適用性與理由，再附主要結論的引文；漏查、不適用或不確定會保留本機初步整理，不採用 AI 治療結論。逐頁自查仍由同一模型完成，不是獨立醫療審核。
- 更新後請重新啟動本機 `npm start`、重新整理原本網址，再依文件庫提示重新解析需要使用的 PDF。不要清除瀏覽器資料，也不需要重新輸入 API key。

```powershell
npm test
npm run audit:nccn
```

`npm test` 使用本機 fixtures 與模擬 AI，不花費 Gemini 額度。PDF audit 讀取 `NCCN_PDF_DIR` 的既有文件，不上傳；內含使用者原乳癌案例、NSCLC 主頁／腳註、直腸癌追蹤分流的真實來源驗收。測試通過不是醫療審核或正式上線許可。

### 7. 備份與還原

1. 進入「設定」，先選「匯出資料備份（不含 PDF）」保存癌別卡、解析索引、checklist、精準欄位與健保資料。
2. 再選「分批備份 PDF」；App 每批最多處理 5 份 PDF，請逐批點擊下載，避免 Android 記憶體不足。
3. 還原時先「匯入資料備份」，再用「匯入 PDF 批次」一次選取一或多個批次檔補回 PDF。
4. v4 備份會記錄備份識別碼、PDF SHA-256 與批次完整度；資料匯入採單一交易，並自動保留匯入前版本供復原。
5. 舊版 v1／v2／v3 JSON 備份仍可匯入。

> ⚠️ 建議將本 App「加入主畫面」安裝使用，定期匯出資料備份，並完成全部 PDF 批次。
> App 會自動要求持久儲存（persistent storage），降低瀏覽器在
> 儲存空間不足時清除本機資料（含 PDF）的風險。

## 資料結構

所有資料儲存於瀏覽器 IndexedDB：

- `cancerCards`：癌別路由卡
- `documents`：PDF 文件元資料，以及 NCCN 的 `nccnStructure` 版本／章節／治療頁索引
- `checklists`：防漏 checklist 項目
- `precisionFields`：精準化欄位定義；病患輸入只保留於目前分頁的 `sessionStorage`，不進入資料備份
- `nhiNotes`：藥物／療程健保資料，並區分完整療程相符、單一成分相關及名稱相似待核對
- `restoreSnapshots`：匯入資料前自動保留的最近 3 份資料索引回復點（不含 PDF）

PDF 檔案本體儲存於獨立的 `OncologyPdfStorage` IndexedDB。

## 全癌別模板

內建 90+ 癌別模板，並對應 NCCN Treatment by Cancer Type 69 項分類。所有癌別都有共同防漏／精準欄位，主要實體腫瘤與血液腫瘤另有癌別專屬的病理、分期與分子標記範本；涵蓋：消化系、胸腔、乳癌、婦癌、泌尿系、頭頸癌、皮膚與黑色素細胞癌、骨與軟組織腫瘤、中樞神經系統腫瘤、血液腫瘤、內分泌與神經內分泌腫瘤等。
